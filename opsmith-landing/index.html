    交付怎么做

    三周，按这个顺序。

    顺序很重要：在亲手把活儿做一遍、确认什么才算“做对”之前，我们不写一行 agent 代码。

    01 / 第一周

    坐进你的队列

    我们两位工程师和你的团队一起处理真实队列。从实际发生的事情里写出操作手册 —— 包括那些从没人记录过的例外情况 —— 并在动手之前，先和你约定一个通过/不通过的指标。

    02 / 第二周

    在真实流量上影子运行

    agent 在你的真实队列上跑，但所有对外动作都关着。它的判断和你团队的判断逐条并排。 你每天看到分歧率，以及它判断错了的那些条目背后的推理过程。

    03 / 第三周

    只上线跑赢的那部分

    我们只在它跑赢基线的那部分流量上开启，用的是你设定的转交阈值。 其余部分继续交给你的团队，直到下一部分也达标。

    大家都会问的部分

    为“随时叫停”而建。

    阈值由你定，用你自己的说法

    金额上限、置信度下限、重点客户，以及任何牵涉别人钱款或身份状态的事。线以下自动跑；线以上，带着完整上下文交给指定的人。

    能回放的审计日志

    每一次输入、判断、工具调用和转交都被记录、可重跑。三月份那张发票为什么那样编码，你一分钟就能答上来，而不是查一周。

    你的系统，你的数据

    每个工作流单独的最小权限凭证，一键撤销。你的数据绝不用于训练模型。可以跑在我们的云上，也可以部署进你自己的 VPC。SOC 2 Type II 审计进行中。

    常被问到的问题

    直说。

    什么算“一个工作流”？
    一个触发、一个结果、一个负责人。“进入 ap@ 的发票被匹配、编码、入账”是一个工作流；“财务”不是。如果你的流程分叉出两个本质不同的结果，那通常就是两个工作流 —— 我们会在第一周就告诉你，在你为第二个付钱之前。
    这是用来裁员的工具吗？
    我们不这么卖，实际情况也不是。到目前为止的每个试点里，同样的团队处理了更大的量，并把时间花在那 3% 真正需要判断力的情况上。如果你买它是为了把团队砍掉一半，那我们大概不是合适的供应商 —— 这些活儿仍然需要有人负责。
    agent 做错了怎么办？
    你会在台账里看到它，连同完整的推理和导致这个结果的输入。可撤销的由同一个 agent 撤销；不可撤销的，会在这次运行之内标记给指定负责人。头一个季度，我们每周复盘每一次转交，并和你一起收紧阈值。错误率超过约定值，这个工作流就回到影子模式 —— 费用由我们承担。
    你们能对接哪些系统？
    常见的后台系统：用友、金蝶、SAP Business One、NetSuite、Zendesk、Salesforce、HubSpot、飞书、企业微信、Shopify、Snowflake，以及任何有 REST API 或 SFTP 投递的系统。如果它只有界面、没有接口，我们就驱动界面 —— 慢一点，照样能跑。第一周就能确定是哪一种。
    为什么要排队，不直接卖？
    因为两位工程师要在你的队列里坐满一周，而我们的工程师就这么多。每批二十家是个诚实的数字。等这不再是瓶颈的那天，等候名单就取消。
